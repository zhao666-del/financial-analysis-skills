# 数据、来源覆盖与声明台账

## 0. 共享有效阅读主账

先由 `research-depth` 建立基金研究包。本文件规定基金专用来源和声明纪律；共享研究包负责有效阅读、深读、去重、来源独立性、递归检索、停止条件和降级。

基金报告必须从 `validation-report.json` 披露发现、粗读、有效阅读、深读、引用、重复来源、原始/一级来源比例、独立来源比例和精准定位完整率。管理人、基金公司和指数公司的原始文件属于重要一手资料，但不自动构成独立证据。

## 1. 来源优先级

按以下优先级使用资料：

1. 基金合同、招募说明书、产品资料概要、定期报告和临时公告；
2. 交易所、监管机构、指数公司、托管人和基金管理人原始文件；
3. 可复算的净值、持仓、成交、利率和基准数据；
4. 独立学术论文、专业方法文件和机构研究；
5. 可靠数据库和数据聚合商；
6. 媒体采访、会议纪要和管理人营销材料；
7. 搜索摘要、自媒体和二次转载只作线索，不支撑核心结论。

同一原始消息的多篇转载只算一个证据。

## 2. 最低覆盖矩阵

完整尽调尽量覆盖：

| 资料类别 | 最低目标 |
|---|---:|
| 年度报告 | 最近3份 |
| 季度或中期报告 | 最近8个报告期 |
| 合同、招募说明书、产品资料概要 | 最新有效版本及重大修订 |
| 经理和团队变更公告 | 全任期关键变更 |
| 基准和指数方法 | 当前版本及重大调整 |
| 同类产品 | 完整定义后的可得母体 |
| 独立方法或学术研究 | 8至15项高相关一手资料 |
| 管理人、量化团队与产品线 | 当前资料及历史关键变化 |
| 合规、运营和重大事件 | 可获得的完整期间 |
| RFI或访谈 | 关键公开信息缺口存在时 |

未达到最低覆盖不必停止研究，但报告状态只能标为“公开资料尽调”或“研究草案”。

## 3. 时间纪律

每个数据集记录：

- `source`
- `effective_date`
- `published_date`
- `fetched_at`
- `basis`
- `coverage`
- `missing_fields`

历史回测只能使用当时已经披露的数据。季度末持仓不能在披露日前被假设为已知。

## 4. 声明台账

每个核心声明建立结构化记录：

```json
{
  "claim_id": "alpha_persistence_01",
  "question": "现任团队是否创造了可重复的费用后超额",
  "claim": "现任阶段超额为正，但统计证据不足以确认稳定阿尔法",
  "facts": [],
  "calculations": [],
  "evidence_for": [],
  "evidence_against": [],
  "alternative_explanations": [],
  "source_quality": "中",
  "source_independence": "中",
  "confidence": "中低",
  "missing_evidence": [],
  "monitoring_metrics": [],
  "invalidation_conditions": []
}
```

声明台账必须同时保存支持和反对证据。没有反对证据时，记录已主动搜索的范围。

## 5. 证据标签

对每项证据标记：

- **类型**：法定披露 / 原始数据 / 管理人陈述 / 独立研究 / 二手资料；
- **质量**：高 / 中 / 低；
- **独立性**：独立 / 可能相关 / 同源；
- **时效性**：当前 / 可接受 / 过期；
- **方向**：支持 / 反对 / 中性；
- **适用范围**：产品全历史 / 经理阶段 / 特定市场阶段。

## 6. 数据冲突

当不同来源冲突：

1. 保留原始值和来源；
2. 检查净值、复权、份额、日期、单位和币种；
3. 优先法定披露和可审计计算；
4. 无法消除时给出区间并降低置信度；
5. 不静默选择更有利于结论的数据。

## 7. 缺失值

缺失不得用主观数字填补。可使用明确标注的方法：

- 近似替代；
- 区间估计；
- 敏感性分析；
- 无法计算。

对归因、容量和同类母体等关键模块，缺失值必须触发评级上限或硬否决检查。

领域内的覆盖表不得覆盖共享研究包状态。若 `research-depth` 返回 `degraded` 或 `blocked`，本 Skill 的任何专用检查均不得将报告升级为完整机构尽调。
