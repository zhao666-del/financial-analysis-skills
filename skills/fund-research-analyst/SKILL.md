# 机构级基金研究与准入尽调

## 研究目标

不要只回答“过去涨得好不好”。必须回答：

1. 收益由资产贝塔、因子暴露、行业配置、证券选择和特殊收益各贡献多少；
2. 超额是否具有统计显著性、跨阶段稳定性和经济意义；
3. 人员、流程、投研平台与模型治理能否支持优势延续；
4. 规模、交易成本、申赎和市场冲击是否会侵蚀优势；
5. 在完整同类池和可替代产品中，它是否值得进入观察名单或组合；
6. 哪些证据不足、哪些反方解释仍成立、什么情况会推翻结论。

## 强制原则

1. 区分事实、计算结果、分析解释、情景假设和未知事项。
2. 每项重要数据记录来源、有效日期、抓取时间和计算口径。
3. 季度持仓只称为报告期持仓；经理业绩按真实任职阶段切分。
4. 同类比较先定义完整母体、去重份额、统一截止日和收益口径。
5. 业绩归因必须先剥离基准与因子暴露，再讨论证券选择能力。
6. 没有显著性与稳健性检验，不得把正阿尔法写成可重复能力。
7. 没有用户组合、风险预算和持有约束，不给精确仓位建议。
8. 不输出无条件买入、卖出、目标收益或保本承诺。
9. 结论必须包含主要反方观点、证据缺口、置信度和失效条件。
10. 先生成结构化研究包，再渲染正文；不得让写作环节改写数字。

## 机构级工作流

1. **标的与任务解析**：确认基金代码、份额、类别、基准、法律形态、用户需要的是研究、比较、准入还是组合适配。
2. **资料覆盖审计**：建立来源矩阵；优先获取合同、招募说明书、产品资料概要、三年年报、八个季度报告、经理变更和重大公告。
3. **产品与母体定义**：识别资产层、产品层和份额层；建立含已清盘或转型样本的同类母体，并设置年龄组和被动替代品。
4. **人员、流程与平台尽调**：按 People、Process、Parent 和运营尽调框架，研究决策权、模型治理、人员稳定、激励、合规、数据与代码控制。
5. **数据标准化与时点检查**：统一累计净值或总回报、基准、无风险利率、复权、频率和披露可得日；记录缺失值和结构断点。
6. **收益与风险诊断**：计算绝对净值与主动净值、滚动和不重叠窗口、主动回撤、修复期、尾部风险、条件贝塔和极端情景表现。
7. **四层阿尔法归因**：依次执行基准相对归因、因子归因、特殊收益归因和经理阶段归因；明确可解释比例与残差。
8. **统计稳健性检验**：报告阿尔法标准误、t值、p值、置信区间、Newey-West调整、区块自助法区间及不同窗口稳定性。
9. **持仓与积极风险分析**：计算主动权重、积极投资比例、行业与因子暴露、前十大主动超配/低配、集中度和主动风险贡献。
10. **容量与流动性压力测试**：量化变现天数、参与率、市场冲击成本、5%/10%/20%赎回情景、受限与跌停资产。
11. **完整同类与替代比较**：输出分位数、同类胜率、费后指标、经理阶段指标，并与低费率被动产品及其他资产载体比较。
12. **证据台账与反方审查**：为每个核心结论登记支持和反对证据；强制执行站在机构拒绝准入立场的 Red Team 审查。
13. **准入与组合结论**：给出准入、条件准入、观察、拒绝或无法评价；列出额度前提、监控项、暂停条件和退出条件。
14. **报告交付**：正文集中呈现决策链，证据附录承载全量表格、回归、同类池、来源矩阵、问题清单和计算说明。写作前读取共享 `research-depth/references/neutral-research-writing.md`，交付前完成中性语言审计。

## 三项硬否决

出现任一项时，不得给出“高确信度准入”或“核心配置”结论：

- 无法区分主要超额来自因子贝塔、证券选择还是一次性特殊收益；
- 团队、投研流程或模型治理信息严重不足，关键人员和控制机制不可核验；
- 无法对策略容量、组合流动性和赎回冲击进行合理量化。

硬否决不等于基金一定差，而是证据不足以支持高等级判断。此时准入上限为“观察”或“条件准入”。

## 核心结论格式

每个重要判断按以下顺序写：

1. 研究问题；
2. 已确认事实；
3. 可复算结果；
4. 最可能解释；
5. 其他合理解释；
6. 不利或反向证据；
7. 条件化结论；
8. 置信度；
9. 缺失证据；
10. 后续监测指标。

## 数据与计算工具

- `scripts/fetch_eastmoney_nav.py`：开放式基金历史净值备用抓取器。
- `scripts/fund_metrics.py`：基础收益、波动、回撤和基准指标。
- `scripts/institutional_diagnostics.py`：主动净值、主动回撤、尾部指标、阿尔法显著性、滚动和不重叠窗口诊断。
- `scripts/capacity_stress.py`：持仓变现天数、市场冲击和赎回压力测试。
- `scripts/validate_research_package.py`：检查来源覆盖、声明台账、三项硬否决、Red Team 和准入上限。
- `templates/research-package.example.json`：机构级研究包字段示例。

定量结论必须来自脚本、结构化表格或可审计模型。数据不足时输出“无法计算”和所需字段，不得编造。

## 输出等级

默认输出两个层次：

- **核心报告**：15至20页等量的信息密度，围绕投资决策组织，不按“一图一页”堆版面。
- **证据附录**：20至40页等量，保存来源矩阵、全量同类池、回归结果、持仓历史、容量假设、声明台账和反方审查。

若用户只要简版，仍必须保留数据日期、关键证据缺口、硬否决检查、反方观点和条件化结论。

## 禁止伪精确

不默认给单一整数总分。每个维度至少输出：

- 评价：强 / 中上 / 中 / 中下 / 弱 / 无法评价；
- 证据质量：高 / 中 / 低；
- 置信度：高 / 中 / 低；
- 趋势：改善 / 稳定 / 恶化 / 不明；
- 关键缺口和结论敏感性。

用户明确要求量化评分时，输出区间、中心值和敏感性分析，并说明硬否决对评级上限的影响。
## 共享有效阅读前置门槛

凡任务需要形成基金评价、比较、经理判断、准入或组合适配结论，必须先调用 `research-depth`，并使用 `--type fund`。只有读取净值、费率或单项公告且不形成研究判断时，才可只调用数据工具。

研究模式映射：

| 本 Skill 任务 | `research-depth` 模式 |
|---|---|
| 快速产品识别、近期表现解释、初步风险提示 | `quick` |
| 单基金评价、多基金比较、财报/季报点评 | `standard` |
| Alpha归因、经理尽调、容量分析和基金深度报告 | `deep` |
| 正式准入、投资委员会、额度审批和组合配置 | `institutional` |

执行顺序：

1. 创建基金 Research Manifest、Source Coverage Matrix 和分支研究计划；
2. 按法律文件、定期报告、经理与团队、People/Process/Parent、归因、持仓、容量、完整同类池、组合适配和反方审查研究；
3. 区分管理人自述、法定披露、可复算数据和独立方法研究，登记阅读范围、证据摘要、独立性和同源关系；
4. 合并去重来源，完成 Claim-Evidence 与精准引用台账；
5. 运行 `validate_research.py`，读取 `validation-report.json` 后再进入定量分析和写作。

报告必须披露：发现数、有效阅读数、深读数、引用数、原始/一级来源比例、独立来源比例、定位完整率、覆盖豁免、覆盖缺口和研究状态。

若返回 `degraded` 或 `blocked`：

- 不得把报告标为“完整机构尽调”；
- 不得给出高置信度Alpha持续性、团队质量、容量或准入结论；
- 必须继承报告标签、置信度上限、覆盖缺口、硬否决和人工取证清单；
- 不得用同一基金公告的媒体转载、净值聚合页面或管理人营销材料凑足阅读量。

已有基金报告更新或审计使用与原报告相同或更高一级的模式，优先验证经理阶段、持仓披露、同类母体和原有投资逻辑是否发生变化。

## 中性客观写作门槛

- 使用基金研究或机构尽调分析师口吻，不使用第一人称、营销语言、交易口号和收益承诺。
- “优秀、稳定、领先、便宜、值得配置”等评价必须绑定同类母体、样本期、费后口径、统计结果和证据质量。
- 管理人陈述写为“管理人表示/文件披露”；未获独立证据或可复算结果支持时，不得改写为研究事实。
- 准入、观察或拒绝是基于当前资料和门槛的条件化状态，不描述为产品的绝对质量。
- 快速产品分析、多基金比较、经理评价、准入报告和组合适配均适用共享规范。
- 对正式草稿运行：

  ```powershell
  python "$env:USERPROFILE\.codex\skills\research-depth\scripts\validate_neutral_language.py" <草稿路径> --out language-audit.json
  ```

- `error` 必须修复；`warning` 逐条补充比较基准或改写。
