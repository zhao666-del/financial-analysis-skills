# 产业深度研究

## 先判断研究对象

在搜集资料前，把任务归入下列一种：

- **行业研究**：主语是一个产品市场、技术赛道、基础设施体系或产业链。使用本 Skill。
- **主题研究**：主语是跨行业变化，例如人工智能基础设施、国产替代、低空经济。使用本 Skill，但先拆出涉及的多个产业系统。
- **公司研究**：主语是一个法律实体、股票或其财务与估值。不使用本 Skill。
- **行业加公司**：先独立完成行业报告，再把公司研究放入单独的配套报告；不得用公司章节替代行业论证。

用户即使提到一家候选公司，只要真正问题是“这个产业如何发展、哪里创造价值、谁可能受益”，仍按行业研究处理。

## 产业链优先原则

产业链分析是本 Skill 的主骨架，不是报告末尾的一张示意图。完成研究边界后，必须先建立全产业链，再研究周期、需求、供给、技术、竞争、利润池和投资映射。

1. 传统制造业至少覆盖：`上游投入 → 核心设备/工具 → 中游加工/制造/集成 → 下游渠道/运营 → 终端客户/付费方 → 售后、回收或再循环`。
2. 软件、平台、医药、金融服务和跨行业主题若不适合机械套用“上中下游”，改用：`基础投入/使能层 → 价值创造层 → 交付/交易层 → 使用/运营层 → 终端需求与付费方`，但不得省略任何关键节点。
3. 把横向能力单独成层：通用设备与工具、算力/数据/软件、研发与制造服务、物流与渠道、知识产权/许可、标准监管、资本与保险。横向能力不因服务多个节点就强行归入某一个上下游。
4. 同时追踪实物/产品、服务、数据、知识产权、资金、责任和风险如何跨节点流动。仅罗列供应商和客户不构成产业链分析。
5. 每个节点都回答：输入是什么、做了什么转化、输出给谁、谁付费、如何定价、何时确认收入、主要成本和资产是什么、有效供给瓶颈是什么、谁掌握控制点、利润和风险如何传导。
6. 公司映射必须区分主角色、跨环节能力和变现方式。产品自研、许可授权、平台服务、代工/CDMO、渠道运营等是不同坐标，不得混成同一个“中游公司”标签。

执行产业链模块前完整读取 [industry-chain-analysis.md](references/industry-chain-analysis.md)。

## 坚守研究层级

1. 把研究单位设为：`终端需求 → 功能/产品 → 全产业链节点与跨节点流 → 工程规格 → 技术路线 → 生产工艺/服务交付 → 有效供给 → 价格与成本 → 利润池 → 竞争结构 → 可投资环节`。
2. 先定义产业边界，再讨论市场规模。说明纳入、排除、替代和互补关系，防止重复计算。
3. 先提出可证伪的产业命题，再组织章节。每条核心结论必须带成立条件、反证和跟踪指标。
4. 区分长周期需求革命、中周期产能资本开支、短周期库存价格。不要把短期涨价等同于长期成长。
5. 区分名义产能和有效供给。有效供给至少考虑利用率、良率、产品结构、认证和爬坡时滞。
6. 技术解释必须走到商业结果：性能变化如何影响单机价值、物料清单、设备材料需求、良率、成本、毛利率和资本回报率。
7. 公司只能出现在竞争格局表、产业链案例卡、客户验证或投资映射中。主报告不得以公司沿革、股权结构、三张财务表、公司盈利预测或目标价为骨架。
8. 对新手使用纯中文解释，首次出现的英文缩写给出中文全称和一句话含义；不得用术语堆砌代替因果关系。

## 执行流程

### 第一步：形成研究简报

写清以下内容：

- 研究对象和地域范围；
- 数据截止日、历史区间和预测区间；
- 核心决策问题；
- 三至七条待验证产业命题；
- 关键争议、未知数和所需数据；
- 最终交付物及篇幅。

用 `scripts/init_industry_project.py` 可生成研究工作区和空白登记表。

### 第二步：建立全产业链主骨架

在历史、需求和技术章节之前完成产业链分析，不得推迟到投资映射阶段：

1. 划分上游、中游、下游、终端需求与售后/回收；不适用传统称谓时，使用功能链或价值交付链并解释映射关系；
2. 为每个节点记录输入、核心活动、输出、客户/付费方、定价与合同、收入确认、关键成本、资产强度、认证/交付时滞、有效供给约束和控制点；
3. 画出实物/产品流、服务流、数据流、知识产权/许可流、资金流和责任/风险流；
4. 单列跨节点横向能力，避免把 AI、软件工具、研发外包、CDMO、许可授权、物流、金融等强行当作单一纵向环节；
5. 建立“公司 × 产业链节点 × 变现方式”角色矩阵，区分主角色、跨环节覆盖、自营与外包；
6. 初步标记利润池、议价权、依赖集中、单点瓶颈和风险传导路径，后续章节逐项验证。

至少产出一张全产业链图、一张节点经济性表、一张公司角色矩阵和一张瓶颈/风险传导图。详细方法见 [industry-chain-analysis.md](references/industry-chain-analysis.md) 与 [report-blueprint.md](references/report-blueprint.md)。

### 第三步：定位历史与周期

复盘重大技术、产品、政策和产能拐点。分别判断：

- 长周期：终端或产品范式是否改变；
- 中周期：资本开支、产能建设和退出是否改变；
- 短周期：库存、订单、价格和稼动率处于何处；
- 政策周期：监管、补贴、贸易和标准是否形成额外冲击。

结论必须说明“现在处在哪一层周期”，不可只展示价格走势图。

### 第四步：重建需求

优先自下而上测算：

`需求额 = 终端数量 × 渗透率 × 单机用量 × 单位价格`

根据行业加入更新率、使用强度、付费率、损耗率或装机利用率。再用行业收入、厂商出货、海关、设备装机或终端保有量作交叉验证。公式和口径见 [models-and-calculations.md](references/models-and-calculations.md)。

### 第五步：重建有效供给

使用：

`有效供给 = 名义产能 × 利用率 × 良率 × 合格产品结构系数`

逐项检查建设周期、设备交期、认证周期、原材料、人才、良率爬坡、切换损失和政策限制。把已公告、在建、试产、认证、量产分开，不将项目规划直接计入可销售供给。

### 第六步：拆解技术与变现

从物理或工程瓶颈出发，比较两条以上技术路线的性能、成本、可靠性、制造难度、生态和量产时间。建立：

`技术指标变化 → 产品规格变化 → 工艺/BOM变化 → 单位价值与成本变化 → 利润池迁移`

按 [technology-to-economics.md](references/technology-to-economics.md) 执行，不以“先进”“领先”代替量产和经济性证据。

### 第七步：研究竞争与利润池

沿已经建立的产业链节点逐环节分析集中度、份额变化、议价权、客户认证、转换成本、规模效应、知识产权、渠道和生态。比较各节点的收入池、毛利池、经营利润池、资本占用和资本回报率，判断价值正在向哪个控制点迁移；不得脱离产业链重新按公司名单叙述。见 [competition-and-profit-pools.md](references/competition-and-profit-pools.md)。

### 第八步：纳入政策与全球分工

分析贸易流、产地、关键设备材料来源、标准制定权、监管许可、补贴和制裁。国产替代必须按产品代际、良率、成本、客户验证和量产份额衡量，不只引用笼统国产化率。

### 第九步：做情景推演与投资映射

至少建立悲观、基准、乐观三种情景，明确假设、供需缺口、价格/利润反应和产业链各节点收益与风险差异。情景冲击必须沿链条传导到订单、价格、库存/利用率、利润和现金流。投资建议的对象首先是**产业环节和商业模式**，再列代表性公司作为观察样本；不输出单一个股目标价。

### 第十步：组装报告并质检

完整报告按 [report-blueprint.md](references/report-blueprint.md) 组装。产业链章节按 [industry-chain-analysis.md](references/industry-chain-analysis.md) 执行。资料规则和质检见 [evidence-and-quality-control.md](references/evidence-and-quality-control.md)。不同产业的特殊调整见 [sector-lenses.md](references/sector-lenses.md)。写作前读取共享 `research-depth/references/neutral-research-writing.md`。生成正文后运行：

```powershell
python scripts/validate_industry_report.py path\to\report.md
python "$env:USERPROFILE\.codex\skills\research-depth\scripts\validate_neutral_language.py" path\to\report.md --out language-audit.json
```

若用户要求 Word 文档，同时使用 documents Skill 完成排版、图表插入、渲染和逐页检查。

## 报告硬门槛

主报告交付前必须满足：

- 给出清晰产业边界和产品分类；
- 把产业链分析置于报告前部并作为后续章节主索引；完整深度报告中该部分通常占正文 15%–25%，复杂产业可更高；
- 给出覆盖上游/使能层、中游/价值创造层、下游/交付运营层、终端需求与售后/回收的全产业链图；不适用项必须解释，不能直接省略；
- 给出产业链节点经济性表，逐节点说明输入、输出、客户/付费方、定价、收入确认、成本、资产、有效供给约束和控制点；
- 给出至少四类跨节点流向，其中必须包含产品/服务流与资金流；知识产权、数据、责任或风险流按行业适用性选择；
- 单列横向能力层，说明工具/设备、软件/数据、外包服务、许可/标准、物流/金融等与纵向节点的关系；
- 给出公司角色矩阵和链条瓶颈/风险传导图；公司不得只按“上游概念股/下游概念股”贴标签；
- 有至少三条可证伪产业命题及反证条件；
- 有一套可复算的需求模型和一套有效供给模型；
- 有当前周期位置及领先指标；
- 有两条以上技术路线对比和技术变现链；
- 有利润池、议价权和资本回报迁移判断；
- 有基准、乐观、悲观情景及敏感性；
- 有按产业链节点和商业模式、而非公司叙事的投资地图；
- 风险写成因果链并给出触发阈值；
- 事实、估算、预测、观点分开标注，关键数字带口径、日期和来源；
- 公司案例不主导目录，不出现公司目标价和公司三表预测。
- 正文不使用第一人称、营销化标签或无条件判断；评价词均有指标、基准和期间。

若任一门槛缺失，先补证据或明确写出数据缺口，不以流畅文字掩盖模型空白。
## 共享有效阅读前置门槛

凡任务需要形成行业、产业链、技术路线、周期、供需或投资判断，必须先调用 `research-depth`，并使用 `--type industry`。只有读取一个确定性统计数字且不形成行业判断时，才可只调用数据来源。

研究模式映射：

| 本 Skill 任务 | `research-depth` 模式 |
|---|---|
| 行业事件解释、单一指标核查、初步产业问题 | `quick` |
| 行业概览、细分环节比较、常规策略简报 | `standard` |
| 行业深度报告、产业链全景、技术路线和投资地图 | `deep` |
| 投资委员会、战略配置、正式产业数据库或长期跟踪底稿 | `institutional` |

执行顺序：

1. 创建行业 Research Manifest、Source Coverage Matrix 和分支研究计划；
2. 按边界口径、全产业链节点与跨节点流、需求、有效供给、价格库存、技术、成本与利润池、竞争、政策全球格局、公司角色矩阵和反方审查研究；
3. 将同一市场规模或产业判断追溯到原始数据，区分厂商自述、交易相关方与独立来源；
4. 登记实际阅读范围、口径、证据摘要和同源关系，合并去重后建立 Claim-Evidence 与精准引用台账；
5. 运行 `validate_research.py`，读取 `validation-report.json` 后再进入产业模型、情景测算和写作。

报告必须披露：发现数、有效阅读数、深读数、引用数、原始/一级来源比例、独立来源比例、定位完整率、覆盖豁免、覆盖缺口和研究状态。

若返回 `degraded` 或 `blocked`：

- 不得把报告标为“完整行业深度研究”；
- 市场规模、供需缺口、渗透率和投资机会只能使用与证据匹配的区间和置信度；
- 必须继承报告标签、置信度上限、覆盖缺口和人工取证清单；
- 不得用重复咨询报告、媒体转述或公司宣传材料凑足阅读量。

已有行业报告更新或审计使用与原报告相同或更高一级的模式，并优先研究新增事实和原结论的失效条件。

## 中性客观写作门槛

- 使用产业研究分析师口吻，陈述产业机制、数据区间和证据边界，不使用宣传口号或情绪表达。
- 将“行业很好、空间巨大、技术领先、确定受益”等表述改为可复算变量、对比指标、兑现条件和时间范围。
- 厂商、协会或政府目标必须标明发布主体；目标值不等于实际需求或可销售供给。
- 快速解释、行业概览、深度报告和投资地图均适用共享中性写作规范。
- `validate_neutral_language.py` 的 `error` 必须修复；`warning` 必须补充量化基准或改写，并保留审计结果。
