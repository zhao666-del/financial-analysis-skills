## 一、目标与完成标准

产业链分析要回答四个问题：价值如何产生、产品或服务如何交付、利润由谁获取、冲击如何传导。完整分析不能停留在“上游原料—中游制造—下游应用”的名单，而要形成可用于需求、供给、技术、竞争、利润池和投资判断的共同坐标。

产业链模块完成时，至少应有：

- 一张全产业链图；
- 一张产业链节点经济性表；
- 一张纵向节点与横向能力的二维图或矩阵；
- 一张公司角色矩阵；
- 一张瓶颈、依赖或风险传导图；
- 每个关键节点至少一项可量化事实和一个待验证问题。

## 二、选择正确的链条表示法

### 1. 传统制造链

适用于材料、零部件、设备、制造和渠道关系较清晰的行业：

`资源/原料 → 设备/工具 → 零部件/材料 → 制造/集成 → 渠道/运营 → 终端客户 → 售后/回收`

### 2. 价值交付链

适用于软件、平台、金融、内容和专业服务：

`基础投入/使能层 → 产品或服务创造 → 分发/交易 → 部署/运营 → 使用者与付费方 → 续费/服务/退出`

### 3. 研发—审批—商业化链

适用于医药、医疗器械和强监管产品：

`科学发现/靶点 → 候选产品 → 临床前/工程验证 → 临床或客户验证 → 注册/准入 → 规模生产 → 商业化/支付 → 上市后管理`

### 4. 项目生命周期链

适用于能源、工程和基础设施：

`资源/规划 → 设计 → 设备材料 → 建设施工 → 并网/验收 → 运营维护 → 退役/更新`

### 5. 多边平台生态

先分别画供给侧、需求侧、平台和基础设施，再标出匹配、支付、数据和责任关系。不要把不同参与方简单排成一条直线。

选择表示法后说明传统“上中下游”分别对应哪些功能节点。跨行业主题先拆成多个子链，再找共享基础设施和系统瓶颈。

## 三、划分产业链节点

节点划分以经济交易或责任边界为准，而不是以公司名称为准。一个节点至少满足下列一项：

- 输出可被下一方采购、许可、部署或使用；
- 存在独立定价、合同或收入确认方式；
- 存在不同的生产工艺、认证、资本强度或风险责任；
- 具有独立竞争者、份额或有效供给约束。

每个节点填写：

| 字段 | 必答问题 |
|---|---|
| 节点功能 | 解决什么问题，完成什么转化 |
| 输入与输出 | 接收什么，交付什么 |
| 客户与付费方 | 使用者、采购者和最终付费方是否相同 |
| 定价与合同 | 按产品、项目、订阅、里程碑、授权或抽成收费 |
| 收入与现金 | 何时确认收入，何时收款，是否存在合同负债或应收 |
| 成本与资产 | 关键原料、人员、设备、库存、资本开支和营运资本 |
| 有效供给 | 产能、利用率、良率、人才、许可、认证和交付时滞 |
| 控制点 | 稀缺资源、核心参数、客户入口、标准、数据或责任牌照 |
| 周期变量 | 订单、库存、价格、利用率、续费、流量或项目开工 |
| 证据边界 | 已验证事实、估算、判断和未知数 |

节点过粗会掩盖利润池，过细会失去决策意义。合并标准是：客户、合同、成本结构和竞争者基本相同；否则保持分开。

## 四、建立六类跨节点流

至少分析产品/服务流和资金流，再按行业选择其他流：

1. **实物/产品流**：原料、部件、成品、库存和所有权何时转移；
2. **服务/交付流**：研发、设计、验证、运维、售后和结果责任由谁承担；
3. **数据流**：数据由谁产生、控制、训练、调用和合规保存；
4. **知识产权/许可流**：专利、配方、软件许可、内容版权和区域权利如何转移；
5. **资金流**：谁付款、付款节点、账期、预付款、里程碑、分成、补贴和融资；
6. **责任/风险流**：质量、库存、召回、性能、合规、残值和信用风险最终落在谁的资产负债表。

同一公司可能控制数据流但不拥有实物流，或取得许可收入但不负责最终生产销售。必须把这些关系分开。

## 五、节点经济性与控制点

沿链条逐节点估算：

```text
节点收入池 = 交易数量 × 单位价格或服务费率
节点毛利池 = 节点收入池 - 可变投入与直接交付成本
节点经营利润池 = 节点毛利池 - 研发、销售、合规和固定运营成本
节点资本回报 = 税后经营利润 ÷ 投入资本
```

数据不足时使用代表企业区间，但要标明样本偏差。将价值创造与价值获取分开：某节点给客户创造巨大价值，不代表其能通过定价、标准、入口或稀缺供给保留利润。

控制点通常来自：

- 稀缺资源或有效产能；
- 决定系统性能上限的参数；
- 高验证成本和高切换风险；
- 数据、标准、专利、牌照或渠道入口；
- 规模、良率学习或网络效应；
- 承担关键责任且难以被替代。

## 六、横向能力与第二坐标

下列能力往往同时服务多个纵向节点，应单独绘制：

- 通用设备、工具和基础设施；
- 算力、数据、软件和自动化；
- 研发、检测、认证、外包制造和专业服务；
- 物流、仓储、渠道和支付；
- 专利、许可、标准和合规；
- 金融、保险和资本。

用“纵向阶段 × 横向能力”矩阵标记覆盖范围、收费方式和责任边界。AI 是跨阶段工具时，不因出现于研发或生产就定义为单一上游；许可授权是权利和变现方式，不是生产工序；CDMO/代工是跨研发、工艺、临床供应或商业生产的服务能力，不应与产品所有者混为一类。

## 七、公司角色映射

公司是产业链证据案例，不是链条本身。角色矩阵至少包含：

| 公司 | 主角色 | 覆盖节点 | 自营/外包 | 主要变现方式 | 核心控制点 | 主要瓶颈 | 不可外推事项 |
|---|---|---|---|---|---|---|---|

遵循：

1. 每家公司指定一个用于组合比较的主角色，同时保留跨节点覆盖；
2. 区分产品所有者、平台、工具、服务商、代工、渠道和资产运营者；
3. 区分产品销售、订阅/服务费、许可/里程碑、按量收费、平台抽成和资产回报；
4. 送样、测试、认证、签署合作、获得许可、建设产能和规模收入是不同阶段；
5. 不因公司覆盖多个节点就宣称“全产业链优势”，必须验证协同、成本、交付和现金回报。

## 八、瓶颈、依赖与风险传导

先识别：

- 单一供应商、单一地区或单一技术依赖；
- 设备、原料、人才、认证、牌照、数据或渠道瓶颈；
- 高客户集中、高库存、高应收、高资本开支或高质量责任；
- 链条中交期最长、替代最慢或损失最大的节点。

风险写成：

`触发事件 → 首个受影响节点 → 数量/价格/交付变化 → 下游或上游传导 → 利润与现金流影响 → 可观察指标 → 失效阈值`

同时检查反向传导：终端需求下降可能先表现为渠道去库存，再压低中游利用率，最后传导到上游价格和资本开支。

## 九、产业链研究输出

完整深度报告将产业链部分放在边界之后、周期和供需之前，通常占正文 15%–25%。建议结构：

1. 全产业链总图与边界；
2. 上游/使能层；
3. 中游/价值创造与转化层；
4. 下游/交付、渠道与运营层；
5. 终端客户、使用者和付费方；
6. 横向能力层；
7. 六类流向与合同/责任关系；
8. 节点经济性、利润池和控制点；
9. 公司角色矩阵；
10. 瓶颈、风险传导和跟踪指标。

快速研究可以压缩篇幅，但不得省略链条边界、关键节点、资金流、控制点和公司角色区分。

## 十、常见错误

- 只按上游、中游、下游列公司，没有输入、输出和交易关系；
- 把横向工具、许可、金融或外包服务硬塞入单一环节；
- 把技术路线、商业模式和产业链阶段当作同一个分类；
- 把集团业务覆盖当成各环节都有竞争力；
- 只画实物流，不画资金、数据、权利和责任；
- 只统计收入池，不比较利润、资本占用和回款；
- 产业链章节与后续需求、供给、技术、竞争和投资章节互不引用；
- 用“概念相关”替代可审计收入、订单、认证、产能、客户和现金流证据。
