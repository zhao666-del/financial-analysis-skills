# Stock Analysis Pro

本 Skill 的研究对象是单一公司或股票。把自动化行情当作入口，把可验证的公司经营因果链、分业务模型和估值反证当作研究主体。深度不等于篇幅；每个重要判断都必须回答“为什么、证据是什么、如何进入财务报表、什么情况会错”。若主语是行业、产业链或技术赛道，改用 `industry-deep-research`。

## 先判定任务

1. **快速分析**：回答最新价格、估值、近期异动和三项核心风险。运行 `brief/summary`，核验最新公告，明确数据缺口，不生成伪深度长文。
2. **标准公司研究**：完成公司、行业、财务、估值和风险分析，适合聊天或十至二十页简报。
3. **产业或公司深度报告**：建立研究问题、证据台账、产业模型、分业务预测和估值情景，通常输出三十至六十页 Word；页数服从证据与模型，不用重复文字凑篇幅。
4. **已有报告升级或审计**：先列出现有结论、证据、模型和反证缺口，再补研究；不要整篇改写掩盖原有问题。

## 核心工作流

### 一、定义研究命题

先写一页研究任务书，至少包含：研究对象与法律主体、数据截止日、可投资证券、三至五个关键争议、市场当前隐含预期、结论可能失效的条件。若公司未上市，明确可投资路径和信息披露边界。

### 二、建立证据台账

优先级为监管与交易所文件、审计财报和招股书、政府与标准组织、客户及供应商原始资料、行业协会与方法透明的数据库、公司官网和业绩会、券商与新闻、社交媒体。关键数字回到一级来源；把事实、推断和预测分栏记录。自动接口返回的数据必须同时记录证券代码、指标、单位、报告期、公告日或交易日、抓取时间、来源名称、来源链接和复权口径；空值不得写成零。

### 三、先建因果模型，后写正文

行业研究至少形成：

- 需求方程：终端数量 × 渗透率 × 单机用量 × 价格，并给出基准、乐观、压力情景。
- 供给方程：名义产能 × 利用率 × 良率 × 单位产出，叠加建设与认证时滞。
- 周期位置：区分长期需求周期、中期产能周期和短期库存周期。
- 技术树：瓶颈、替代路线、性能成本权衡、量产节点和受益环节。
- 利润池：价值量、毛利率、议价权和资本回报向哪个环节迁移。

公司研究至少形成：

- 分业务收入树、单位经济性、客户与地区结构。
- 产品能力对照表和客户验证证据。
- 价格、销量、结构、成本、费用、汇率及一次性项目的利润桥。
- 资产负债表、现金流、资本开支、库存与应收的交叉验证。
- 治理、股权、管理层激励、关联交易和资本配置判断。

### 四、技术必须穿透到财务

按“物理或工程瓶颈 → 技术路线 → 制造步骤 → 良率与成本 → 客户价值 → 认证与量产 → 收入和毛利 → 资本回报”分析。实验室样品、送样、小批量、量产和规模盈利必须分开。未披露量产收入的技术只能列为可选项，不进入基础预测。

### 五、建立预测与估值

逐业务预测数量、价格、收入和毛利率，再汇总费用、税率、少数股东、资本开支、营运资金和股本。至少采用两种估值方法；多业务公司优先分部估值，周期公司使用正常化利润，未盈利公司使用里程碑情景和现金消耗。加入反向估值：当前价格要求公司实现什么收入、利润率和持续时间。

### 六、先反驳自己

对每条核心投资逻辑写出最强反方观点、先行指标和失效阈值。风险不得只写“需求不及预期”；必须说明传导链、可观测指标、可能影响和应对方式。

### 七、写作与交付

结论先行，但正文按证据链展开。区分事实、计算、假设、分析判断和未验证信息；不使用第一人称、情绪化修饰、营销化标签或无条件预测。凡使用“高/低、改善/恶化、领先/落后、低估/高估”等评价，必须同时说明指标、比较对象、期间和证据。图表必须服务于一个判断并标明口径、单位、日期和来源。使用 documents Skill 生成纯中文版 Word，更新目录并逐页检查分页、表格、图像、引用、空白页和脚注。

## 交付前硬性门槛

- 法律主体、证券代码、股本、报告期和数据截止日一致。
- 三至七个决定性结论均有一级或交叉来源支持。
- 行业空间不是只引用一个总规模，必须展示可复算的需求驱动。
- 供给分析包含产能、利用率、良率、扩产时滞或行业等价指标。
- 每条核心业务均有市场、产品、客户、竞争和财务预测闭环。
- 至少完成基准、乐观、压力三种情景及敏感性分析。
- 明确区分合并利润、归母利润、扣非利润和自由现金流。
- 写出反证、跟踪指标和结论失效条件。
- 缺失数据明确标记“未披露/无法核验”，不得用零值或行业平均替代公司事实。
- 正式草稿已运行共享中性语言检查；硬性问题为零，限制性用词均已补充量化基准或改写。

## 安全与边界

- Cookie 仅保存在被 Git 忽略的本地配置，不在聊天、报告或日志中回显。
- 外部数据 Skill 是固定版本的代码与接口参考，不是权威事实源；只执行完成当前任务所需的最小代码片段，并先检查网络目标、写入路径和密钥读取范围。
- 实时接口、券商报告和新闻只能提供线索；重大投资数字必须回到法定披露核验。
- 不把相关性写成因果，不把目标市场总额直接当公司收入，不把订单意向当确认收入。
- 不承诺收益；评级必须绑定估值区间、假设和风险承受条件。
## 共享有效阅读前置门槛

凡任务需要形成公司、股票、估值、比较、财报或投资判断，必须先调用 `research-depth`；公司研究统一使用 `--type company`。只有读取一个确定性行情或公告事实且不形成研究判断时，才可只调用数据 Skill。

研究模式映射：

| 本 Skill 任务 | `research-depth` 模式 |
|---|---|
| 最新异动解释、快速分析、三项风险、初筛 | `quick` |
| 常规公司分析、财报点评、股票比较、报告审计 | `standard` |
| 公司深度报告、完整盈利预测、技术商业化和多方法估值 | `deep` |
| 股票池准入、投资委员会、正式评级或额度决策 | `institutional` |

执行顺序：

1. 创建公司 Research Manifest、Source Coverage Matrix 和默认研究分支；
2. 按法定披露、业务分部、财务质量、治理与资本配置、技术商业化、行业周期、客户供应链、同业、估值和反方审查检索；
3. 将来源区分为发现、粗读、有效阅读、深读和引用，登记章节/页码、证据摘要、独立性和同源关系；
4. 合并去重来源，完成 Claim-Evidence 与精准引用台账；
5. 运行 `validate_research.py`，读取 `validation-report.json` 后再进入本 Skill 的财务模型、估值和写作。

报告必须披露：发现数、有效阅读数、深读数、引用数、原始/一级来源比例、独立来源比例、定位完整率、覆盖豁免、覆盖缺口和研究状态。

若返回 `degraded` 或 `blocked`：

- 不得输出“完整机构级报告”、高置信度评级或高置信度目标价值；
- 精确目标价必须改为条件区间或暂停估值；
- 必须继承报告标签、置信度上限、覆盖缺口和人工取证清单；
- 不得在写作阶段用篇幅、二手资料或重复新闻补足门槛。

已有报告升级或审计使用与原报告相同或更高一级的模式，新增资料必须进入同一研究包，不能另建一份无法追溯的来源清单。

## 中性客观写作门槛

- 写作者身份是研究分析师，不是公司宣传者、交易喊单者或第一人称评论员。
- 结论采用“证据与日期 → 计算或机制 → 条件化判断 → 置信度 → 失效条件”，不使用“我认为/我们认为”。
- 公司自述写为“公司披露/管理层表示”；未获独立验证时不得转换为事实语气。
- 快速分析、聊天答复、财报点评和正式报告均适用同一标准。无法运行脚本的聊天答复，按共享规范人工复核。
- 对 Markdown、文本或 Word 草稿运行：

  ```powershell
  python "$env:USERPROFILE\.codex\skills\research-depth\scripts\validate_neutral_language.py" <草稿路径> --out language-audit.json
  ```

- `error` 必须修复后再交付；`warning` 逐条核验，有数据基准则补充，没有则删除或改写。
