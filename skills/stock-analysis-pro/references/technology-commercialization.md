## 一、技术研究的八层结构

对半导体、材料、装备、医药、新能源、人工智能等技术企业，按以下顺序研究：

1. **问题**：客户当前被什么性能、成本、可靠性或监管约束卡住。
2. **原理**：技术如何解决问题，核心变量是什么。
3. **路线**：有哪些竞争路线，各自权衡是什么。
4. **制造**：需要哪些设备、材料、步骤、人员和知识产权。
5. **指标**：性能、良率、成本、寿命、功耗、安全和一致性。
6. **验证**：样品、认证、定点、临床、量产和复购处于哪一步。
7. **商业**：客户为什么付钱，价值量和定价方式是什么。
8. **财务**：收入、毛利、资本开支、营运资金和资本回报如何变化。

任何一层缺失，都不能把技术领先直接写成投资价值。

## 二、原理解释

先用一段新手语言解释，再给专业层：

- 新手层：使用日常类比说明输入、过程和输出。
- 专业层：说明物理、化学、生物或算法机制和关键公式。
- 指标层：列出客户真正比较的三至七个参数。
- 系统层：说明该技术在整机、生产线或业务流程中的位置。

避免只翻译缩写。解释一个参数提高后，哪些成本、功耗、寿命或其他指标会恶化。

## 三、路线比较

建立路线矩阵：

|路线|核心原理|性能|成本|制造兼容|生态|成熟度|主要玩家|
|---|---|---|---|---|---|---|---|

重点寻找：

- 路线是互补还是替代。
- 客户是否必须更换设备、软件或供应链。
- 旧产能能否改造，还是必须新建。
- 更高参数是否带来更高系统总成本。
- 路线领先是否受专利、标准或关键材料限制。

不要因为某路线理论上更优就假设会胜出；制造兼容、客户迁移和总体拥有成本经常决定商业结果。

## 四、制造与良率

技术从设计到利润通常经过：

`设计/配方 → 样品 → 工艺窗口 → 设备匹配 → 小批量 → 良率爬坡 → 客户认证 → 稳定量产`

研究：

- 关键工序和最难控制的缺陷。
- 实验室设备与量产设备差异。
- 原材料纯度、供应稳定和回收。
- 良率、节拍、单位产出和报废。
- 规模扩大后热、力、电、化学或软件稳定性问题。
- 售后、质保、召回和现场服务成本。

制造企业的技术变现常见方程：

`单位成本 ≈ 材料 + 能源 + 人工 + 折旧 + 良率损失 + 质保`

先进工艺只有在单位合格产出增加、成本下降或售价提升时才创造经济价值。

## 五、客户验证

建立成熟度梯子：

|阶段|可写结论|不可写结论|
|---|---|---|
|论文/专利|证明有研究和知识产权布局|已形成产品壁垒|
|实验室样品|参数在特定条件下可实现|可稳定量产|
|工程样品|接近客户应用环境|客户已采用|
|送样测试|客户正在验证|获得确定订单|
|定点/入围|进入项目或供应商体系|保证最终销量|
|小批量|工艺和客户初步通过|规模利润稳定|
|量产|形成收入和交付|高毛利可持续|
|多客户复购|商业模式可复制|永远领先|

医药行业用临床前、各期临床、申报、获批、入院和放量替换；软件使用测试、试点、合同、上线、续费和扩席。

## 六、科技如何进入利润表

至少选择一条可复算路径：

1. **涨价**：性能或稀缺性提高平均售价。
2. **增量**：新应用增加销量或单机用量。
3. **份额**：认证和可靠性替代竞争者。
4. **降本**：良率、材料、节拍、能耗或自动化改善单位成本。
5. **平台化**：同一研发平台复用到更多产品，摊薄研发和销售费用。
6. **授权与服务**：专利、软件、耗材和维保形成持续收入。
7. **资本效率**：同一产线产出更多价值，减少新增资本开支。

建立技术变现桥：

`参数提升 → 客户系统收益 → 客户愿付价格/采购量 → 公司份额和价格 → 单位毛利 → 研发与资本开支 → 自由现金流`

若客户系统收益无法量化，技术溢价需要更保守。

## 七、路线图和成熟度

路线图至少包含：

- 当前量产代际。
- 已送样或认证的下一代。
- 研发中的远期路线。
- 竞争者对应节点。
- 客户平台导入时间。
- 旧产品淘汰和自我蚕食。
- 量产需要的资本开支和人员。

将技术项目分成基础预测、乐观情景和长期可选项。只有量产能力、客户验证和产能计划三者齐备，才进入基础预测。

## 八、常见误判

- 专利数量等于专利壁垒。
- 参数领先等于系统性能领先。
- 送样等于订单，定点等于收入。
- 新技术只增加售价，不增加成本和资本开支。
- 国产替代自动带来更高毛利。
- 领先一代可以永久保持；忽略竞争者路线图。
- 实验室效率直接复制到大规模生产。
- 总市场很大，所以公司一定能获得足够份额。
- 人工智能相关就等于能直接获得高带宽、高毛利业务。

技术章节结尾必须给出“已证明、待证明、无法证明”三栏，并说明下一次验证节点。
